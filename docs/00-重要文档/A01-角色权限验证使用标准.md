# A02-角色权限验证使用标准

## 文档概述

本文档规范了若依AI平台中角色权限验证的使用标准，明确了角色key和角色id的使用场景，确保代码的一致性和可维护性。

## 1. 核心原则

### 1.1 使用角色Key进行权限验证
- **业务逻辑验证**：始终使用角色key (`UserConstants.RoleKeys.*`)
- **权限检查**：使用角色key进行用户权限验证
- **条件判断**：在业务流程中判断角色类型时使用角色key

### 1.2 使用角色ID进行数据操作
- **数据库操作**：使用角色id (`UserConstants.RoleIds.*`) 进行数据库CRUD操作
- **关联关系**：在用户角色关联表中存储角色id
- **接口参数**：前端传递角色选择时使用角色id

## 3. 使用规范

### 3.1 ✅ 正确的权限验证方式

#### 方式一：使用角色key验证权限
```java
/**
 * 验证用户角色权限 - 推荐方式
 */
private R<Void> validateUserRole(String requiredRoleKey, String roleName) {
    // 检查用户是否具有指定角色key
    boolean hasRole = LoginHelper.getLoginUser().getRolePermission().contains(requiredRoleKey) ||
                     LoginHelper.isSuperAdmin();
    
    if (!hasRole) {
        return R.fail("权限不足：只有" + roleName + "角色才能执行此操作");
    }
    
    return R.ok();
}

// 使用示例
R<Void> roleValidation = validateUserRole(
    UserConstants.RoleKeys.DESIGNER, 
    UserConstants.getRoleDisplayName(UserConstants.RoleKeys.DESIGNER)
);
```

#### 方式二：检查用户已有角色
```java
/**
 * 检查用户是否已具有专业角色
 */
private boolean hasSelectedProfessionalRole(List<SysRoleVo> userRoles) {
    for (SysRoleVo role : userRoles) {
        String roleKey = role.getRoleKey();
        if (UserConstants.RoleKeys.DESIGNER.equals(roleKey) || 
            UserConstants.RoleKeys.ENTERPRISE.equals(roleKey) || 
            UserConstants.RoleKeys.SCHOOL.equals(roleKey)) {
            return true;
        }
    }
    return false;
}
```

### 3.2 ✅ 正确的数据操作方式

#### 角色选择和分配
```java
/**
 * 角色选择 - 使用角色ID进行数据库操作
 */
@PostMapping("/selectRole")
public R<Void> selectRole(@RequestBody SelectRoleRequest request) {
    // 1. 使用角色key进行权限验证
    boolean hasPermission = validateUserPermission();
    
    // 2. 使用角色ID进行数据库操作
    Long targetRoleId = request.getRoleId();
    Long[] allowedRoleIds = {
        UserConstants.RoleIds.DESIGNER_ROLE_ID,
        UserConstants.RoleIds.ENTERPRISE_ROLE_ID,
        UserConstants.RoleIds.SCHOOL_ROLE_ID
    };
    
    if (!Arrays.asList(allowedRoleIds).contains(targetRoleId)) {
        return R.fail("无效的角色选择");
    }
    
    // 3. 数据库操作使用角色ID
    SysUserRole userRole = new SysUserRole();
    userRole.setUserId(userId);
    userRole.setRoleId(targetRoleId);  // 使用角色ID
    userRoleMapper.insert(userRole);
    
    return R.ok();
}
```

## 6. 常见问题和解决方案

### 6.1 问题：权限验证失败
**现象**：用户有相应角色但权限验证失败

**原因**：使用了角色ID进行权限验证

**解决方案**：
```java
// ❌ 错误写法
if (role.getRoleId().equals(UserConstants.RoleIds.DESIGNER_ROLE_ID)) {
    // 权限验证逻辑
}

// ✅ 正确写法  
if (UserConstants.RoleKeys.DESIGNER.equals(role.getRoleKey())) {
    // 权限验证逻辑
}
```

### 6.2 问题：数据库操作失败
**现象**：角色分配或查询时出现类型错误

**原因**：在数据库操作中使用了角色key

**解决方案**：
```java
// ❌ 错误写法
userRole.setRoleKey(UserConstants.RoleKeys.DESIGNER);

// ✅ 正确写法
userRole.setRoleId(UserConstants.RoleIds.DESIGNER_ROLE_ID);
```

## 9. 总结

- **权限验证**：始终使用角色key (`UserConstants.RoleKeys.*`)
- **数据操作**：始终使用角色ID (`UserConstants.RoleIds.*`)
- **注解优先**：优先使用`@SaCheckPermission`注解进行权限控制
- **保持一致**：同类功能使用相同的验证标准
- **文档更新**：修改代码时同步更新相关文档
