# 短信发送问题诊断指南

## 🔍 问题现象
- 日志显示"短信验证码发送成功"
- 但手机实际没有收到短信

## 📋 诊断步骤

### 1. 检查阿里云API详细响应
查看服务器日志中的详细响应信息：
```
阿里云短信API响应 - phone: xxx, success: true, message: xxx, data: xxx
```

### 2. 常见原因分析

#### 🔸 **账户问题**
- **余额不足**: 阿里云账户短信余额不足
- **账户状态**: 账户被限制或冻结

#### 🔸 **配置问题**
- **AccessKey/Secret**: 密钥配置错误
- **Endpoint**: 接口地址配置错误
- **签名问题**: `signName` 未审核通过或配置错误

#### 🔸 **模板问题**
- **模板ID**: `SMS_324450504` 模板不存在或未审核
- **模板参数**: 参数格式不匹配

#### 🔸 **手机号问题**
- **号码格式**: 手机号格式不正确
- **运营商限制**: 某些运营商可能有限制

#### 🔸 **频率限制**
- **发送频率**: 超过了阿里云的发送频率限制
- **日发送量**: 超过日发送上限

## 🛠️ 解决方案

### 1. 验证阿里云控制台配置

#### 检查短信服务状态
1. 登录阿里云控制台
2. 进入"短信服务"
3. 检查以下内容：
   - 账户余额是否充足
   - 签名是否审核通过
   - 模板是否审核通过

#### 验证当前配置
```yaml
# application-dev.yml
sms:
  enabled: true
  endpoint: "dysmsapi.aliyuncs.com"
  accessKeyId:   # 检查是否正确
  accessKeySecret:   # 检查是否正确
  signName: 亿思湖北省科技  # 检查签名是否审核通过
```

### 2. 验证模板配置

在阿里云控制台检查模板 `SMS_324450504`：
- 模板是否存在
- 审核状态是否通过
- 参数格式是否为 `${code}`

### 3. 测试步骤

#### Step 1: 检查日志
重新发送验证码，查看完整日志：
```bash
# 查看详细响应
grep "阿里云短信API响应" logs/ruoyi-admin.log
```

#### Step 2: 手动测试
使用阿里云控制台的"发送测试"功能直接发送短信验证

#### Step 3: 更换测试号码
尝试使用不同的手机号码测试

### 4. 常见错误码对照

| 错误码 | 说明 | 解决方案 |
|--------|------|----------|
| SignatureDoesNotMatch | 签名验证失败 | 检查AccessKey/Secret |
| InvalidTemplate.Malformed | 模板格式错误 | 检查模板参数格式 |
| isv.TEMPLATE_MISSING_PARAMETERS | 模板参数缺失 | 检查参数映射 |
| isv.AMOUNT_NOT_ENOUGH | 账户余额不足 | 充值账户 |
| isv.DAY_LIMIT_CONTROL | 日发送量限制 | 等待次日或申请提额 |
| isv.SMS_SIGNATURE_ILLEGAL | 签名不合法 | 使用已审核的签名 |

## 🔧 临时解决方案

如果需要临时绕过短信发送进行测试，可以：

1. **使用固定验证码**（仅开发环境）
2. **记录到日志文件**供测试查看
3. **使用邮箱验证**作为备用方案

## 📞 技术支持

如果问题仍无法解决：
1. 收集详细的API响应日志
2. 联系阿里云技术支持
3. 提供具体的错误码和请求ID

## 🎯 最佳实践

1. **监控余额**: 设置余额告警
2. **日志记录**: 保留详细的发送日志
3. **错误处理**: 对不同错误码做不同处理
4. **降级方案**: 准备邮箱验证等备用方案
