## 1. 实施概览

### 1.1 实施目标
根据《设计师模块逻辑删除标准规范》，对企业任务删除接口 `DELETE /designer/enterprise/tasks/{id}` 进行重构，实现逻辑删除替代物理删除，提高数据安全性和可恢复性。**最新调整：任务恢复和回收站查询功能仅对系统管理员开放**。

### 1.2 核心修改内容
- ✅ **Task实体类增强**：添加 `@TableLogic` 注解和逻辑删除字段
- ✅ **服务层扩展**：新增逻辑删除、恢复、回收站查询等方法
- ✅ **控制器重构**：修改删除接口实现逻辑删除，新增恢复和回收站接口
- ✅ **数据库迁移**：添加逻辑删除字段和性能优化索引
- ✅ **权限配置**：为新功能添加相应权限控制
- ✅ **权限调整**：恢复和回收站功能改为仅系统管理员可访问

## 2. 权限模型调整

### 2.1 权限分级说明

#### 2.1.1 企业管理员权限
- ✅ **任务删除**：可以逻辑删除自己企业的任务
- ❌ **任务恢复**：无权恢复已删除的任务
- ❌ **回收站查询**：无权查看已删除的任务

#### 2.1.2 系统管理员权限
- ✅ **任务删除**：可以删除任何企业的任务
- ✅ **任务恢复**：可以恢复任何已删除的任务
- ✅ **回收站查询**：可以查看所有企业的已删除任务
- ✅ **企业过滤**：可以通过企业ID过滤特定企业的删除任务

### 2.2 权限调整理由
1. **数据安全性**：避免企业管理员误恢复或查看其他企业的删除数据
2. **审计控制**：系统管理员统一管理删除数据，便于审计和监管
3. **职责分离**：企业管理员专注业务操作，系统管理员负责数据治理
4. **合规要求**：符合数据保护法规对敏感操作的权限控制要求

### 4.1 修改的接口

| HTTP方法 | 路径 | 变更内容 | 权限要求 | 影响 |

| DELETE | `/designer/enterprise/tasks/{id}` | 物理删除 → 逻辑删除 | 企业管理员 | 向后兼容，数据更安全 |

## 6. 使用场景

### 6.1 企业管理员场景
```
1. 企业管理员登录系统
2. 在任务列表中找到需要删除的任务
3. 点击删除按钮（逻辑删除）
4. 任务被标记为删除，不再显示在列表中
5. 如需恢复，联系系统管理员处理
```

### 6.2 系统管理员场景
```
1. 系统管理员登录系统
2. 访问任务回收站：GET /designer/enterprise/tasks/recycle
3. 查看所有已删除任务（可按企业过滤）
4. 选择需要恢复的任务
5. 调用恢复接口：POST /designer/enterprise/tasks/{id}/restore
6. 任务恢复到正常状态
```

### 6.3 企业过滤示例
```bash
# 查看所有已删除任务
GET /designer/enterprise/tasks/recycle

# 查看指定企业的已删除任务
GET /designer/enterprise/tasks/recycle?enterpriseId=123

# 组合查询条件
GET /designer/enterprise/tasks/recycle?enterpriseId=123&taskTitle=LOGO&pageNum=1&pageSize=10
```

## 8. 风险评估和缓解

### 8.1 权限模型风险
- **风险**：系统管理员权限过于集中
- **缓解**：
  - 严格的系统管理员账户管理
  - 详细的操作审计日志
  - 定期权限审查机制

### 8.2 业务流程风险
- **风险**：企业管理员无法自主恢复数据
- **缓解**：
  - 建立快速响应流程
  - 提供企业管理员删除确认机制
  - 系统管理员24/7值班制度

### 8.3 数据安全风险
- **风险**：系统管理员可以访问所有企业数据
- **缓解**：
  - 最小权限原则实施
  - 数据访问日志记录
  - 定期安全审计
